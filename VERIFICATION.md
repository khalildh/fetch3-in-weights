# Verification

## v0.2: compiled DNS and HTTPS together

The default pipeline now executes two compiled circuits: DNS and fetch3. They have separate token streams and are sequenced by Python. This remains the NumPy integer reference, not a GPU or autonomous LLM run.

The real-network handoff test disabled `socket.getaddrinfo` for the whole run. The DNS circuit selected `104.20.23.154`, and the actual HTTPS socket peer was exactly that address. TLS 1.3 certificate verification and SNI used `example.com`. Both circuit streams matched their specifications; replay reproduced both token hashes with socket creation disabled.

Additional checks:

- Seven focused offline tests passed, covering rendered HTML, replay, changed-query rejection, DNS UDP behavior, circuit-triggered TCP retry, circuit-triggered AAAA fallback, and circuit refusal of a private address.
- Real resolver TCP retry: a synthetic TC first response triggered a real TCP query/reply. Both the UDP and TCP requests were generated by the DNS circuit. All 185 positions matched the specification.
- Real resolver AAAA fallback: synthetic A NODATA triggered a real AAAA query/reply; the circuit selected an IPv6 address. All 238 positions matched the specification. This does not claim an IPv6 HTTPS connection.
- Normal real resolution of `www.iana.org`: all 191 positions matched the specification and the independently parsed address agreed.
- Those DNS-only live traces also replayed identically with sockets disabled.

The fallback trigger responses are deliberately synthesized, not naturally observed server behavior. Receipts label this explicitly. Sanitized evidence is in [`verification/`](verification/); raw DNS/HTTP responses are excluded.

## v0.1: fetch3 with host DNS

Checked on Apple Silicon on 2026-11-07 using the standalone repository's own environment.

- Offline circuit execution and exact replay: passed. Socket creation was disabled in the test. The rendered page includes text and a numbered link and excludes the fixture's script/comment contents.
- Modified-request replay rejection: passed.
- Live HTTPS to `https://example.com`: completed at `<|fetch_done|>` with one TCP connection, TLS 1.3, certificate verification, 134 request bytes and 928 raw response bytes. Circuit and specification agreed at all 1,103 token positions.
- Replay of that recorded live response: identical token-stream hash, zero network connections.

The live request SHA-256 was `d358038dbaa59af084ae0b874f4cfac45a756b2655e5172f2d67032b059e69a7`. The token-stream SHA-256 was `36d23e164285d9510996ade222ea92b106cadc8c9e7ad6bb0120cfa107f9bcf8`.

Fresh live runs may differ because real HTTP responses include changing headers and content. Replay of one saved response must reproduce that run's exact token hash. Raw network recordings are deliberately excluded from this repository.

This verifies a Python/NumPy execution of the exported circuit. It does not verify GPU execution, autonomous model navigation, or compatibility with arbitrary websites.
